Lighting a piece at Revel

You've been handed a song and a list of cues, in whatever shape they wrote it. This is how to turn that into a ShowXpress show that plays on Revel's lights, using the setup we already have from the Teen Titans showcase. Everything up to the last section needs no programming.

Revel's lights

13 Chauvet SlimPAR 56 LED pars in 7-channel mode, patched by Revel. Each mixes any colour. The numbers match the stage map Revel gave us.

Each light has 7 channels, in this order: red, green, blue, colour macro, shutter, mode, dimmer. Colour is the red/green/blue mix (0–255 each). Brightness is the dimmer. Keep colour macro, shutter and mode at 0: anything else turns on the light's own built-in colours, strobe or effects, which won't be in time with the music.

CH13 is in Revel's patch but not on the map. The starter's "find each light" scene lights it last, so you can see where it is.

1. Set up Everyone

Do this once per piece. It gives you a ShowXpress show with Revel's lights already patched and placed in the 3D view, so you don't patch anything by hand.

  1. Install ShowXpress (steps in the ShowXpress guide, section 1). ShowXpress is also sold as The Lighting Controller; it's the same program.
  2. In ShowXpress, File › New lightshow, named after the piece. Then quit with Cmd + Q.
  3. Download the starter:
  4. Double-click the zip in Downloads. It makes a folder called revel-showxpress-starter.
  5. Open Terminal (Cmd + Space, type Terminal, Enter) and paste this, with your show's name in the quotes: 
    bash ~/Downloads/revel-showxpress-starter/install.sh "Show name"
    It finishes with Done. Run it without a name and it lists your shows.
  6. Open ShowXpress, File › Open lightshow, pick the show. Editor › Fixtures should list CH1 to CH13.

The starter adds four scenes to build from: 00 blackout, 01 all warm white fade in, 02 all white, and 03 find each light (each light alone in white for 2 s, in number order). It also adds a "Timing test" timeline (see For programmers). Running it again is safe: it puts back Revel's patch and 3D layout but never replaces a scene that's already there.

Shows live in your home folder at ~/TheLightingController/LightShows; File › Open lightshow Folder opens it. Not the lightshows_bank folder next to the app: files put there are ignored.

2. Turn their cue list into times Everyone

Get the exact music file the show will play. Every time is measured against that file; a re-export that starts a little later shifts every cue. A video of the piece helps too.

Cue lists arrive as lyrics ("blue when she sings 'falling'"), counts ("8 counts into the chorus"), bars, rough times, or a feeling. Whatever the shape, rewrite it as a table first, using Revel's light numbers:

TimeLightsColourLevelHowUntil
0:00.00alldark0—
0:04.321–12lime / lavender100%snapnext cue
0:27.54allwarm white100%fade 2 s
0:57.667white100%snap on, fade out 0.3 s, ×40:58.26

Finding the times

  • Play the song in anything that shows the time to a tenth or better (an audio editor, or this site's lighting page). A hit lit 0.2 s late looks late.
  • For counts, find the first count of the phrase, then the beat length: 60 ÷ BPM seconds. At 120 BPM a count is 0.5 s, and an "&" lands halfway between.
  • If a figure repeats, time it once and copy it. The repeat is usually the same distance apart.

Ask the performer when it's unclear

These are where we got it wrong the first time:

  • "Fade": fade in, fade out, or blend from one colour to another? How long?
  • When does it stop? "Chaos in the last section" turned out to mean two separate bursts.
  • Which lights? "Light her up" might mean her pole at full and everything else dimmed.
  • Read the rhythm back to them ("1, and 2, &?"). People mis-say counts; we lost a round to it.

Then show them something (a recording of the 3D view, below) as early as you can. Most of our big changes came from the performer seeing it.

3. Make the looks Everyone

A scene is a saved look, or a sequence of them. Each step in a scene sets channels and has a duration; each channel either snaps or fades into the step, and a fade takes the step's whole duration (V9 manual p1, p13). Go to Editor › Steps: each light gets a row of 7 faders.

One look

  1. New scene, or open 00 blackout and Save scene as a new name, so you start with every light set to dark.
  2. For each light in the look, set red, green and blue for the colour and the dimmer for brightness. Click a value to type it.
  3. Check the small fade / snap icon under each fader. Right-click a fader › Set "fade" state of channel on all steps does a whole column at once.
  4. Type the step's Duration in the step list. It's minutes:seconds.hundredths, so 00:02.00 is two seconds.
  5. Save scene as. Name it so it sorts in show order: 05 warm white fade.

Scenes are instructions, not snapshots. Revel's own programming notes put it this way: a channel the scene doesn't set keeps whatever value it had, so to turn a light off you have to set it to 0. Forgetting to zero something is the most common mistake. Starting every scene from 00 blackout avoids it.

Revel's notes also say: keep each scene simple, and make more of them rather than fewer.

Fades

A 2-second fade is a 2-second step with its channels on fade. To fade and then stay, add a second step with the same values on snap, held as long as the look lasts (01 all warm white fade in is built that way).

Multi-step scenes loop (V9 p26, "Loop"). If the last step is too short, the scene starts over and runs its fade again. We hit this when a hold step meant to last minutes lasted 6 seconds.

Hits, pulses and strobes

  • Hit: step 1 snaps on, held for the hit (say 0.05 s); step 2 fades to dark over 0.3 s.
  • Pulse or breathing: steps alternate full and about 35% dimmer, all on fade, each a beat long.
  • Strobe: steps alternate on and off, on snap. ShowXpress plays steps in 0.05 s ticks and rounds each one up (we measured it: 40 steps of 0.07 s took 3.97 s, not 2.8 s). Make every step a multiple of 0.05 s, or fast runs drift off the beat.
  • Ripples and chases: Editor › Generator draws a curve per channel with a delay between lights (V9 p15–16). Or make the steps by hand with each light a little later.

Flashing more than 3 times a second is the usual photosensitivity line (WCAG 2.3.1 is the web version).

Looks that worked at Revel

  • Solos: the soloist's apparatus (7 or 3 for pole, 10 for loops) warm white at full, the other apparatus dark, the floor at about 55% in soft colours.
  • In busy sections keep the dancer's light at full and the floor lower (we used 50%), so they don't disappear.
  • Snaps for punchy intros. Hits that snap on and fade away. Crossfades for calm passages.
  • The backdrop (11) with the soloist's colour ties the picture together.
  • Pick a palette and stay in it. The Teen Titans logo's own lavender looked grey-blue on screen, so we used a bluer #9b72ff. Not yet checked on the real lights.

4. Put it on the song Everyone

Use the TimeLine when the show should play itself with the music. Go to Live › TimeLine.

  1. Menu › TimeLine settings: set the duration longer than the song, and turn on Media timelines so there's a row for the music (V9 p25, p27).
  2. Make the song a WAV: ShowXpress only draws the waveform for WAV (V9 p27), and the waveform is how you see where the hits are. In Terminal: afconvert -f WAVE -d LEI16 song.mp3 song.wav. Keep it in the show's folder, so everything for the piece is in one place.
  3. Right-click the music row › Add Media file, and pick the WAV (V9 p25).
  4. Right-click a light row › Add Steps scene, and pick a scene (V9 p25).
  5. Right-click the block › Move to › specific time, and type the cue time (V9 p26). Dragging isn't precise enough. The timeline works in tenths of a second. Zoom in and out with keypad +/−; PgUp/PgDn scroll.
  6. Make each block last until the next one starts.
  7. Save the timeline (V9 p25).

To play: Play runs from the start. To start partway, double-click the top of the timeline to put the red marker there, then Play from red marker (V9 p25–26).

Starting partway, remember scenes are instructions. Whatever was set before the red marker hasn't run, so a light can be in the wrong state until something sets it. If a look is wrong only when starting partway, play from earlier.

Layers. A timeline can have several light rows, and Revel's notes use overlapping layers. Because a scene only changes what it sets, a scene on one row can change the floor while another row's scene runs the poles. Keep one job per row (say, poles on row 1, floor on row 2) so two rows never set the same light at once.

Not confirmed: what happens if two rows do set the same channel at once. How to set a block's length in the app (dragging its edge is my best guess; the manual doesn't say).

We saw lights blink at the joins between blocks, especially near snaps and short fades. What fixed it: joins inside a held look, at least a quarter second from any snap.

Or: press GO by hand Everyone

To cue live, or as a backup, put scenes on buttons in Live › Buttons (V9 p20–24).

  • Page menu › Add Steps scene for each look, in cue-list order.
  • Page menu › Solo buttons, so pressing one look turns the last one off. Otherwise scenes stack.
  • Button menu › Button trigger › Keyboard gives each one a key.
  • Button menu › Flash button lights it only while held. Good for a strobe the operator hits on the music.
  • Live settings › Fade in/out time between scene buttons sets a crossfade between them (V9 p22).
  • Page menu › Add TimeLine puts a whole timeline on one button (V9 p20).

5. Check it Everyone

  1. Unplug the DMX adapter. The 3D view only drew for us with no adapter connected.
  2. Windows › 3DView. The starter already put each light where it is on Revel's map. Open 03 find each light in the Editor and play it to check.
  3. In Live, top right, the cube is 3D output and the icon beside it is DMX. A green line under one means it's on.
  4. In Editor › Steps, turn the DMX and 3D buttons off. The Editor overrides Live, so with them on, the timeline seems to do nothing.
  5. Play it. Windows › DMX Bargraph shows the actual numbers going out, if the 3D view is confusing (V9 p4).
  6. Record the 3D view for the performer: Cmd + Shift + 5 › Record Selected Portion. ShowXpress has no video export, and the Mac recorder doesn't capture the sound, so add the song afterwards.
  7. At Revel: plug the adapter in, make sure DMX has its green line, play.

When it's wrong Everyone

What you seeWhat it was for us
A light stays on when it shouldn't.No scene set it back to 0. Scenes are instructions.
Music plays, lights don't.3D output off, or the Editor's DMX/3D buttons on (they override Live).
Editor › Fixtures is an empty grid.The starter isn't installed in this show, or the show is in the wrong folder. Run the install again with the show's exact name.
Your timeline isn't in the Open list.A different show is open (check the title bar).
Lights lag or drift from the music.Play a bit, stop, then start over. Revel's notes say this refreshes it.
Fades slam on.The step duration is far shorter than meant. It's in hundredths: 00:02.00 is 2 s.
A look keeps re-fading.The scene looped. Make its last step long.
Fast flashes drift off the beat, or one goes missing.Step lengths not on the 0.05 s tick, or a block join in the middle of a run.
Lights blink off for an instant.A block join at a bad moment. Move it into a held look.
A light strobes or changes colour on its own.Colour macro, shutter or mode isn't 0.
The install script says ShowXpress is open.Quit it with Cmd + Q (closing the window isn't enough).

For programmers: generate the files Programmers

Typing dozens of scenes is slow and error-prone. Everything ShowXpress reads is plain text, so for a long piece a script is faster. Quit ShowXpress before writing. After the starter, a show folder looks like:

~/TheLightingController/LightShows/<show>/
  fixtures.ini                    Revel's patch: [FixtureN] address, name, model, id
  fixtures/SlimPAR 56 (7CH).txt   channel order and ranges
  scenes/*.scex                   one XML file per scene
  Live/TimeLine/timelines/*.tml   ini, one [Event_N] per block
  3DView/fixtures.ini             where each light sits in the 3D view

A scene

<Scene>
  <Fixtures>
    <Fixture id="1685573658" name="CH1: SlimPAR 56 (7CH)" model="SlimPAR 56 (7CH)"/>
  </Fixtures>
  <Steps>
    <Step length="200">
      <Fixture id="1685573658">
        <Channel index="0" value="255" fade="1"/>
        …
        <Channel index="6" value="255" fade="1"/>
      </Fixture>
    </Step>
  </Steps>
</Scene>
  • Fixture ids come from fixtures.ini (venue/fixtures.ini in this folder). Channel index 0 is red, 6 is dimmer.
  • length is hundredths of a second. Playback rounds each step up to 0.05 s, so keep lengths multiples of 5.
  • fade="1" fades across the whole step; 0 snaps.

Or reuse this site's generator

showxpress.js already does all of this for Revel's rig from a cue plan: blocks joined at safe moments, steps on the 0.05 s tick, every scene setting every channel. It's tested against the plan across the whole song (test/showxpress.test.mjs). Write the piece's cues as a plan in this app's format (README.md, and normalizeCue in cues.js), open the page with ?edit, import it, and use Download for ShowXpress. SXP_SHOW in app.js names the show it installs into.

The starter's "Timing test" timeline flips the stage 40 times at 0.25 s, then 40 times at 0.07 s. Run it after any ShowXpress update. If the second half takes 2.8 s instead of about 4 s, the tick has changed.
